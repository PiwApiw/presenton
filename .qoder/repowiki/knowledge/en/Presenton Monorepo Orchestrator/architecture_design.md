The root `start.js` is the single process supervisor: it creates the shared `/app_data` directory tree (userConfig.json, exports, images, uploads, fonts, templates, pptx-to-html/json), synchronizes the pinned presentation-export runtime via `scripts/sync-presentation-export.cjs`, optionally installs Ollama when `START_OLLAMA=true`, then spawns FastAPI (`servers/fastapi/server.py`) on port 8000, an App MCP server on 8001, Next.js (`servers/nextjs`) on 3000, and Nginx as the external-facing reverse proxy. Child processes are tracked in a managed set so SIGINT/SIGTERM shuts them down together; dev mode restarts FastAPI/Next.js on clean exit and reloads the mounted `nginx.conf`. The Electron desktop app (`electron_desktop_app`) reuses this same runtime but embeds the servers internally and exposes renderer IPC. `docker-compose.yml` defines four services (`production`, `production-gpu`, `development`, `development-gpu`) sharing one massive environment block of LLM/image/search provider keys, with GPU variants adding NVIDIA device reservations. Build & distribution tooling (`build_scripts`) converts templates and syncs the export-core runtime referenced by both the Electron package and the Docker image, while CI/CD (`ci_and_deploy`) consumes the same Dockerfiles and scripts to publish images and Electron binaries.
