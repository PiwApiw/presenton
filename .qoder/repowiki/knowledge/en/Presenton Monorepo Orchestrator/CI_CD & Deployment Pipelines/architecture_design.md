Two parallel deployment surfaces live side-by-side:
- `.github/workflows/` — four GitHub Actions workflows: `docker-release.yml` builds multi-arch (linux/amd64 + linux/arm64) images to GHCR on release or manual dispatch; `electron-linux-ubuntu22.yml` builds .deb/.AppImage artifacts on an Ubuntu 22.04 runner and publishes them as a prerelease in a separate `presenton/presenton-export` repo; `sync-releaes-to-r2.yml` mirrors published release assets to Cloudflare R2 via rclone using the `sync_r2` environment; `test-all.yml` runs repository tooling tests, FastAPI pytest suite, and Next.js lint/build/Cypress component tests on push/PR to main.
- `.do/deploy.template.yaml` — DigitalOcean App Platform manifest declaring a single `presenton` service pulling from `ghcr.io/presenton/presenton`, with runtime env vars (`MIGRATE_DATABASE_ON_STARTUP`, `START_OLLAMA`) and DEPLOYMENT_FAILED/DOMAIN_FAILED alerts.
- `.github/FUNDING.yml` declares the project's GitHub Sponsors funding target.
Dependency direction is one-way: workflows depend on secrets/environments (`RELEASE_REPO_TOKEN`, `R2_ACCESS_KEY`, `R2_SECRET_KEY`, `R2_ACCOUNT_ID`, `sync_r2`) and on the built image/tag produced by `docker-release.yml`; the DO template consumes that GHCR image but has no CI dependency.
