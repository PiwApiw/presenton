Scripts are independent CLI utilities with no shared runtime — each file is self-contained and invoked directly via `node` or `python3`. Two sub-families coexist:
- Template conversion: `convert-template.mjs` provides the core `convertTemplateData`/`convertTemplate` API (asset planning, path rewriting, static directory cleanup); `convert-presentation-template.mjs` layers presentation-to-template transformation on top of it.
- Runtime provisioning: `sync-presentation-export.cjs` downloads a pinned `@presenton/export-core` tarball from GitHub Releases into `presentation-export/`, validates Sharp native deps for the current platform/arch, and writes a version manifest; `run-presentation-export.mjs` is the installed runner that invokes `@presenton/export-core.runTask` with cookie/desktop-origin configuration derived from env vars.
- Config normalization: `user-config-env.cjs` exposes a typed pipeline (`readUserConfigEnv` → `normalizeConfigTypes` → `normalizeImageConfig`) over a fixed whitelist of `USER_CONFIG_ENV_KEYS`.
- License aggregation: `rebuild_notice_all.py` scans Python site-packages and Node `node_modules` to rebuild the repo-level `NOTICE` file.
Dependency direction is one-way: higher-level scripts import lower-level ones (e.g. `convert-presentation-template.mjs` imports `convert-template.mjs`), never the reverse. Each script guards its own entry point via `process.argv[1]` / `require.main === module` checks so they can be both CLI tools and imported by tests.
